# Continuous Work Context

Professional systems must feel like part of the employee's work, not links to unrelated labs.

## Context bridge
Every work item receives a stable context ID.

When an employee launches GitHub, AWS or another professional system:
1. Practice Studio creates a short-lived contextual launch.
2. The external environment receives only the minimum identity/scope it needs.
3. Relevant observations are normalized through the adapter.
4. Evidence returns to the same work context.
5. The employee resumes the same matter with evidence already attached.

The product must not expose secrets or embed hidden world state in launch URLs.

## Evidence normalization
GitHub repository permissions and AWS/IAM entitlements use a common permission-observation shape. This lets the employee compare evidence without pretending the providers are identical.

## Clarification
Questions to managers, requestors, system owners and colleagues stay attached to the work context. Response delay follows workplace-time rules.

The employee should be able to leave a matter waiting for someone else and perform other work in the meantime.

## UX rule
Do not present a vendor-logo launcher as the primary experience.

Systems should appear because the current work requires them. The work item remains the organizing object.
