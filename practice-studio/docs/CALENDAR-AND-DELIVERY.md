# Workplace Calendar and Event Delivery Rules

## Principle
Practice Studio should behave like an organization, not a timed quiz.

## Default operating rhythm
- Monday to Friday
- 9:00 AM to 5:00 PM enterprise local time
- routine events outside those hours are queued for the next work period
- urgent events may surface immediately where the role legitimately requires it
- weekends are non-working by default
- tenant-specific holidays can be configured

## Delayed responses
Simulated people should not answer every message instantly.

Response timing can depend on:
- role;
- availability;
- complexity;
- meeting status;
- workday boundaries.

The authoritative response schedule is generated by the engine, not improvised by the conversational model.

## Overnight events
Systems can change while the employee is away.

Examples:
- monitoring alert;
- failed authentication attempts;
- repository workflow failure;
- cloud resource drift;
- client email sent from another time zone.

These events can alter enterprise state before the employee returns. Routine events are presented at the next work period unless urgency policy says otherwise.

## Deadlines
Deadlines use business time, not raw wall-clock time, unless the workplace explicitly defines an after-hours/on-call expectation.

The UI should be able to distinguish:
- on track;
- attention required;
- due.

Do not display artificial countdowns unless a real workplace deadline exists.
